## Context

We want living docs on GitHub Pages: static, but interactive enough to hold
clickable mocks, interactive designs and illustrated decisions. The research
notes in `docs/` must keep reading well on GitHub. The app is React with its
own design tokens, and the team is Python-first. Everything should be open
source and cheap to run.

## Decision

Use **Astro Starlight** in `docs-site/`, deployed to GitHub Pages by a GitHub
Actions workflow on every push to `main`.

- `docs/` stays the source of truth for written notes. A sync script adds
  the frontmatter Starlight needs and rewrites links at build time.
- Interactive pages are `.mdx` files that embed React components, hydrated
  only when visible.
- The theme imports `web/src/design/tokens.css`, so the docs use the app's
  colours and fonts.
- The web mock is built with its in-browser mock API and served at `/app/`
  on the same site, so pages can embed it.

## Consequences

- Good: one place for research, mocks, decisions and test evidence, with
  full-text search (Pagefind) and no server.
- Good: a decision illustration is a small React component, so it can grow
  into a real prototype.
- Bad: a second Node project to keep up to date next to `web/`.
- Revisit if the docs need versioning per release or if Starlight stalls.
