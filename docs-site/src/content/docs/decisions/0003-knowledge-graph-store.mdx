## Context

The graph links properties, people, land titles, territories, embargoes and
risk results. Every relation carries `source`, `snapshot_date` and
`confidence`, so each flag in a report traces back to a record. Geometry
stays in PostGIS; the graph holds H3 cells and overlap results. Sebas prefers
TypeDB because its typed schema *is* the ontology
([technical requirements §3](../../research/technical-requirements/)).

The scores below are a first pass from the caveats in the technical

what the phase-0 spike must measure.

## Decision (proposed)

Use **TypeDB 3.x**, with `schema/core.tql` as the ontology. Keep Neo4j as
the fallback if the spike fails.

The spike passes when:
- `schema/core.tql` loads and sample data from the pilot municipality inserts.
- Multi-hop questions ("which borrowers' properties overlap an embargo
  through a shared owner?") return in under a second.
- An LLM with few-shot examples writes correct TypeQL for most of the golden
  questions used by the talk-to-the-data layer.

## Consequences

- Good: no separate OWL layer to keep in sync; provenance fits naturally on
  n-ary relations.
- Bad: an RDF mapping is needed for partners who want GeoSPARQL or FIBO.
- Revisit after the spike; then mark this record accepted or superseded.
